エージェント モードで GitHub Copilot を使うと、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、開発者のマシンでリアルタイムに実行される各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更を個別に採用または却下し、フォローアップのプロンプトで会話を調整できます。エディターを離れる必要はありません。

この演習では、次の内容を学習します。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- 作業中のセッションを調整し、高コントラストに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、高コントラスト モードを実装中です。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライト モードの切り替えも追加してほしいと依頼がありました。新しい会話を始める代わりに、既存セッションを調整して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取り、編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは停止して **Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントが高コントラスト モードを実装し終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライト モードを追加するよう依頼する

高コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。同じ Chat セッションを使うため、エージェントは変更した component、採用したスタイル、設定済みの local storage のパターンなど、前の作業のコンテキストを保持しています。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが変更内容を調べ直し、ライト モードの追加を提案する様子を確認します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合（たとえば、気に入らない方法でトグル UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、明確なフォローアップを送ります。

> [!TIP]
> 作業中のセッションを調整すると、最初からやり直すより短時間で進められます。フォローアップのプロンプトで変更（「CSS を簡潔にし、selector の重複ではなく CSS 変数を使う」）、方向修正（「3 つ目のトグルは追加せず、既存の設定パネルにライト モードを組み込む」）、範囲の拡張（「両方のトグルにキーボード ショートカットも追加する」）を依頼できます。

## 変更ファイルをレビューする

commit する前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro component、スタイル、関連 test が更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン（Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定保持）が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視し、各ファイルの編集を確認し、変更を採用 / 却下し、コンテキストを保ったままフォローアップのプロンプトを送って作業を拡張しました。

この演習では、次の内容を学習しました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に採用 / 却下する。
- フォローアップ プロンプトで作業中のセッションを調整する。
